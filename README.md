# Beyond Issues: Requirement-Driven LLM Agents for Software Issue Resolution

Official implementation of the paper:

Beyond Issues: Requirement-Driven LLM Agents for Software Issue Resolution

## 💡 1. Overview
<img src="./overview.pdf" alt="overview" width="1000">
This repository contains six parts:

### 📊 1. **Requirement Generation Component**  

All files related to the requirements generation component are located in the `Requirement_Generation\`. The folder structure is as follows:
```
Requirement_Generation\
├── find_requirement.py
├── reqgen_lv\
└── reqgen_pro\
```

### 📊 2. **Requirement Assessment Component**  

All files related to the requirements assessment component are located in the `Requirement_Assessment\`. The folder structure is as follows:
```
Requirement_Assessment\
├── generate_patch.py
├── generate_testcase.py
├── optimize_testcase.py
├── compare_patch.py
├── create_compared.py
├── Test_LV\
└── Test_Pro\
```

### 📊 3. **Requirement Refinement Component** 

All files related to the requirements refinement component are located in the `Requirement_Refinement\`. The folder structure is as follows:
```
Requirement_Refinement\
└── feedback.py
```

### 📊 4. **Datasets** 

The `Datasets\` folder contains the three benchmarks used in our experiments. For each benchmark (SWE-bench Lite, SWE-bench Verified, and SWE-bench Pro), we sample 100 instances and provide them in both JSONL and Parquet formats. The folder structure is as follows:
```
Datasets/
├── Lite.jsonl
├── Verified.jsonl
├── Pro.jsonl
├── Lite.parquet
├── Verified.parquet
└── Pro.parquet
```

### 📊 5. **Results** 

The `Results\` directory contains all intermediate and final outputs generated by REAgent during the problem-solving process. The folder structure is as follows:
```
Results/
├── patch
│   ├── deepseek
│   │   ├── Lite
│   │   │   ├── Compared
│   │   │   └── Generated
│   │   ├── Pro
│   │   │   ├── Compared
│   │   │   └── Generated
│   │   └── Verified
│   │       ├── Compared
│   │       └── Generated
│   └── qwen
│       ├── Lite
│       │   ├── Compared
│       │   └── Generated
│       ├── Pro
│       │   ├── Compared
│       │   └── Generated
│       └── Verified
│           ├── Compared
│           └── Generated
├── feedback\
├── requirement\
├── testcase\
└── testresult\
```
It consists of the following five components:

1. **requirement**: Stores the generated issue-oriented requirements.

2. **patch**: Stores patches generated based on the requirements.

3. **testcase**: Stores test cases generated from the requirements.

4. **testresult**: Stores the execution results of patches on the generated test cases.

5. **feedback**: Stores feedback information used for iterative refinement.

Specifically, the `Generated\` directory contains the most recently generated requirements, patches, and test results in the current iteration, while the `Compared\` directory stores the optimal requirements, patches, and test results selected during the greedy optimization process.

### 📊 6. **repos**

The `repos\` directory is used to store the repositories involved in the problem-solving process. Please clone the required repositories into this directory according to the data provided in `Datasets\`.

## 🚀 2. Experiments

### 🛠️ 1. **Setup** 

```
pip install -r requirement.txt
```

Before running REAgent, please pull all required images to the local environment and ensure that the image names follow the official naming conventions of SWE-bench and SWE-bench Pro.

### 📝 2. **Requirement Generation** 

We adopted the Trae-agent scaffolding framework to implement the requirement generation process in REAgent. For detailed information about this framework, please refer to the Trae-agent page.  

The `Requirement_Generation/reqgen_lv` directory implements the generation process for SWE-bench Lite and SWE-bench Verified, while `Requirement_Generation/reqgen_pro` handles SWE-bench Pro. As an example for SWE-bench Verified, first update your model API information in `Requirement_Generation/reqgen_lv/evaluation/trae_config.yaml`, then execute the following command in the `Requirement_Generation/reqgen_lv/` directory:

```
python -m evaluation.run_evaluation \
  --benchmark SWE-bench \
  --dataset SWE-bench_Verified \
  --config-file evaluation/trae_config.yaml \
  --run-id <model_ite> \
  --max_workers <parallel workers> \
  --ite <Iteration> \
```
* `--benchmark`: Name of the benchmark, keep as `SWE-bench` here
* `--dataset`: Specific dataset name, can choose `SWE-bench Lite` or `SWE-bench Verified`
* `--config-file`: Location of the `trae_config.yaml` file
* `--run-id`: Run ID, usually named as `model_ite`, e.g., `qwen_1`
* `--max_workers`: Number of parallel workers
* `--ite`: Current iteration number

Additionally, when --ite is non-zero, the system enters Iterative Optimization Mode, leveraging feedback information to refine requirements.

The execution results are saved in Requirement_Generation/reqgen_lv/results/<benchmark_dataset_run-id>/, with the output for each instance stored in a subfolder named <instance_id>.

Once the generation is complete, run the following command to extract the requirements:

```
python find_requirement.py --ite <Iteration> --model <qwen or deepseek> --dataset <Lite or Verified or Pro>
```

The final requirements will be saved in `/REAgent/Results/requirement/<model>/<dataset>/Generated/Requirement<ite>`.

### 📝 3. **Requirement Assessment**

1. **Patch Generation**
   
Run the following command to generate patches:

```
python generate_patch.py --ite <Iteration> --model <qwen or deepseek> --dataset <Lite or Verified or Pro>
```

The program will automatically handle path extraction, fault file retrieval, and patch generation. The patches are saved in `/REAgent/Results/patch/<model>/<dataset>/Generated/patch<ite>` (`/REAgent/Results/patch/<model>/<dataset>/Compared/patch<ite>` when ite=0). We also provide a `patch.json` in this folder for easier subsequent testing.

2. **Test Cases Generation (executed only once)**
   
This step must be executed after the patch is generated. Run the following command:

```
python generate_testcase.py --model <qwen or deepseek> --dataset <Lite or Verified or Pro>
```

The generated test cases are saved in `/REAgent/Results/testcase/<model>/<dataset>/test0.jsonl`。

3. **Test Excution**
`Requirement_Assessment/Test_LV` is used for SWE-bench Lite/Verified testing, while `Requirement_Assessment/Test_Pro` is used for SWE-bench Pro.

For SWE-bench Lite/Verified, navigate to `Requirement_Assessment/Test_LV` and execute:

```
python run_avgpass.py \
  --test_jsonl /REAgent/Results/testcase/<model>/<dataset>/test0.jsonl \
  --run_id <dataset>_<model>_Generated_<ite> \
  --num_workers <parallel workers> \
  --dataset /REAgent/Datasets/<dataset>.parquet \
  --predictions_path /REAgent/Results/patch/<model>/<dataset>/Generated/patch<ite>/patch.json \
```
* `--test_jsonl`: Path to the test cases.
* `--run_id`: Run ID, typically formatted as `<dataset>_<model>_Generated_<ite>` or `<dataset>_<model>_Compared_<ite>`.
* `--num_workers`: Number of parallel workers
* `--dataset`: Path to the datasets.
* `--predictions_path`: Path to the JSON file containing patches to be evaluated.

After the testing is completed, we run the following command to collect the results:

```
python logread.py --dataset_patch /REAgent/Datasets/<dataset>.parquet --log_patch ./logs/run_evaluation/<run_id>/ --patch_path /REAgent/Results/patch/<model>/<dataset>/Generated/patch<ite>/patch.json
```

And for SWE-bench Pro, navigate to `Requirement_Assessment/Test_Pro` and execute:

```
python repro_regre.py \
  --raw_sample_path external_hf_v2.csv \
  --model_patch_path /REAgent/Results/patch/<model>/Pro/Generated/patch<ite>/patch.json \
  --test_patch_jsonl /REAgent/Results/testcase/<model>/Pro/test0.jsonl \ 
  --output_dir logs/reproregre/<model>_<ite> \
  --scripts_dir run_scripts \
  --num_workers 10
```
* `--raw_sample_path`: Path to the dataset CSV file.
* `--model_patch_path`: Path to the JSON file containing patches to be evaluated.
* `--test_patch_jsonl`: Path to the test cases.
* `--output_dir`: Path for logging outputs, typically `logs/reproregre/<model>/<ite>`.
* `--scripts_dir`: Path to the required execution scripts
* `--num_workers`: Number of parallel workers.

After the testing is completed, we run the following command to collect the results:

```
python logread.py --dataset /REAgent/Datasets/Pro.parquet --log_patch ./logs/reproregre/<model>_<ite>/ --patch_path /REAgent/Results/patch/<model>/Pro/Generated/patch<ite>/patch.json
```

Finally, the test results are saved in `/REAgent/Results/testresult/<model>/<dataset>/Generated/result<ite>.jsonl` or `/REAgent/Results/testresult/<model>/<dataset>/Compared/result<ite>.jsonl`

4. **Patch Selection (executed when greedy selection is required)**
   
Following our greedy optimization strategy, a comparative selection between the current results and the best results from the previous iteration is required after each test. Run the following:

```
python compare_patch.py --ite <Iteration> --model <qwen or deepseek> --dataset <Lite or Verified or Pro>
python create_compared.py --ite <Iteration> --model <qwen or deepseek> --dataset <Lite or Verified or Pro>
```

The selection results are saved in the `/Compared` directory within each results folder.

5. **Test Case Optimization (executed when test cases have been generated)**
   
After each iteration, we optimize the error test cases. Run the following command:

```
python optimize_testcase.py --ite <Iteration> --model <qwen or deepseek> --dataset <Lite or Verified or Pro>
```

The optimized test cases are saved in `/REAgent/Results/testcase/<model>/<dataset>/test<ite>.jsonl`。

Note: Since test cases are optimized across iterations, the "best patch" currently selected via the greedy strategy must be re-tested using the newly optimized test cases. In subsequent iterations, newly generated patches will be evaluated against the latest test cases and compared with the previous best result to ensure continuous improvement.

### 📝 4. **Requirement Refinement**

1. **Feedback Generation**

Run the following command to generate feedback information:

```
python feedback.py --ite <Iteration> --model <qwen or deepseek> --dataset <Lite or Verified or Pro>
```

The feedback analysis report is saved in `/REAgent/Results/feedback/<model>/<dataset>/feedback<ite>.jsonl`.
By setting `--ite` to a value greater than 0 in the generation phase, the Agent will automatically load this feedback to perform iterative requirement optimization.

The final patches can be evaluated using the Golden Tests provided by SWE-bench or SWE-bench Pro.
